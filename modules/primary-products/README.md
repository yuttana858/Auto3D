# Primary Products 0.16.0

Independent bottle/can/pouch/closed-clamshell UI and neutral geometry package, API 1. No Auto3D engine, account or Packaging imports. Auto3D integrates its lazy module bundle through separate host adapter/workspace services.

`CreatePrimaryProduct(draft, {segments: 64})` returns indexed component meshes (flat position/normal/UV/index arrays), canonical-mm bounds and physical front/back/wrap zones plus a circular bottle `cap-top` zone. Tessellation is bounded to multiples of four from 16–128. Basic bottle components are body/cap; basic can components are body/top/bottom. Detailed construction adds the components described below. Base-centered origin, Y-up; outside height includes the closure. `GetArtworkZones(draft)` describes cylindrical or section-following zones on the straight body and the printable cap disc. Body UVs are profile coordinates; separate label patches supply the artwork UVs.

`ProductDefinition(draft)` and `ValidateProductDefinition(value)` provide strict versioned authoring metadata. File/recovery validation can import this lightweight file without loading geometry or UI.

Saved explicit material choices are retained: older plastic/PET definitions are not migrated to glass. Regenerating a glass bottle uses the current glass shell. Optional `details` adds nominal inner walls, shaped shoulders and closures, can seams/tabs, and clamshell rim/hinge/latch components. Hinges and caps are shown closed; threads and articulation remain future work. Not for capacity or engineering claims. The Auto3D host enables scene generation and atomic update/Undo; clear glass/PET use physical transmission. Glass uses the open-mouth construction described below; PET retains its presentation envelope. The profile drawing is illustrative. Local label artwork maps onto generated surfaces through the host; the independent 3D draft preview remains future work.

The module-owned panel receives inspect/configure/reset/generate/update/loadSelected/units/blocked functions from a neutral host. Controls update a matching selected generated product live; without that selection they configure a draft for Generate. The host serializes rebuilds, preserves placement and camera framing, and groups rapid updates for Undo. Drafts survive panel changes within the account, and reset when accounts change.

Standalone: `npm install`, `npm test`, `npm run build` in this folder. Root `npm run build_primary_products` and website builds emit separate lazy JS/CSS assets.

See [the build plan](../../docs/primary-products-build-plan.md) and [scene increment](../../docs/release-0490.md).

Pouches use `DefaultProductDraft("pouch")`, with widthMm, heightMm and depthMm (filled outside envelope). Material is opaque plastic; labels are front/back zone descriptors. Round products retain diameterMm. `Generate` availability follows host editor readiness without rebuilding draft controls. See [0.50.0](../../docs/release-0500.md).

Category material presets expose real PBR defaults through `ListProductMaterials`. `ValidateProductArtwork` validates physical zones; `CreateLabelMesh` creates conforming patches. Authoring definitions may include front/back labels or one wrap, plus a bottle cap label (at most three bounded descriptors). Original bytes remain in embedded material maps supplied by the host. The panel receives artworkOpen/artworkMapping/artworkRemove/artworkPreview callbacks. Dimensions use one H × W × D row, with linked round W/D and a native material color swatch. See [0.52.0](../../docs/release-0520.md).

Optional `bottleShape` contains all four canonical-mm fields: `neckDiameterMm`, `shoulderHeightMm`, `neckHeightMm`, `capHeightMm`. Missing shape data retains the original proportional profile. Explicit profiles keep a straight body of at least 20% overall height and a cap within the body diameter. Labels are bounded to the remaining straight body; incompatible existing labels block draft mutation. See [0.55.0](../../docs/release-0550.md).

The catalog contains 43 original illustrative designs across bottles, cans, beverages, pouches and unified clamshell browsing. The API is exposed through `ProductCategories`, `ListProductDesigns` and `ProductDesign`. The panel accepts catalog/selectDesign callbacks and opens an animated bottom drawer. Clamshells use the rectangular envelope fields and top/bottom art, stored as front/back zone IDs. See [catalog research](../../docs/primary-product-catalog-research.md) for sources, design limits and material presets.

Clamshell browsing is unified under the fourth Product card (`clamshells`), with legacy food/retail command filters retained. Label controls mount inside the host advanced material editor and preserve custom body surfaces. Release 0.59.0 introduced a closed presentation envelope for glass/PET; glass now uses the open-mouth construction below. The host persists transmission/IOR/thickness through rendering, archives and GLB/glTF. See [0.59.0](../../docs/release-0590.md).

## Realistic construction and surfaces (0.13.0)

All 43 catalog presets enable optional `details`: `wallMm`, `textureStrength` (0–1), `textureScaleMm` (1–100), plus family-specific `shoulder`, `closure`, `canStyle` or `shellStyle`. `ValidateProductDetails` validates explicit edits and clamps nominal wall thickness on size changes. Set `details: null` to retain the basic construction. Canonical dimensions remain the outside envelope. Walls at tight seams are presentation approximations, not a manufacturing offset solver.

`ScaleProductChanges(draft, factor)` scales dimensions, bottle profiles and pouch fitments; nominal walls remain fixed subject to fit. Host `primary.scale` optionally scales artwork dimensions and offsets, preserves object identity and edited body materials, and creates one Undo step. The neutral panel receives `setDetails` and `scaleProduct` callbacks.

`ProductSurfaceMaps` returns deterministic, embedded bump/normal/packed-roughness PNG maps with a bounded cache. Physical texture tiling is supplied by the host adapter. The module depends on `fflate` only for portable PNG encoding. Material presets add frosted/amber glass, natural HDPE, frosted PP, satin pearl plastic and clear pouch film. The host persists clearcoat and clearcoat roughness in archives and glTF.

Artwork descriptors accept `finish`, `offsetXmm` and `offsetYmm`. Finish options are matte/textured paper, gloss/satin film, foil and clear gloss film. Transparent artwork preserves its existing alpha; this does not remove a white background. Existing image import remains in the advanced material editor. The 0.16.0 CAD workflow below adds editable cut and artwork layers while keeping these placement and finish controls.

See [0.62.0](../../docs/release-0620.md) and [reference research and follow-up gates](../../docs/primary-product-realism-research.md).

## Live profile editor (0.14.0)

`ProductProfileEditor(host, root)` renders actual-geometry front/top projections and editable callouts. The neutral host supplies `inspect`, `blocked`, `update` and `close`; the panel supplies `openProfile`. `ProfileChanges(draft, changes)` validates atomic product-space edits shared by UI and commands. Dimension inputs honor metric/standard units. The current live-input path applies valid edits after a short debounce and flushes on Enter or blur, while preserving incomplete decimal input. Bottle shape controls use fixed closure dimensions while overall-height edits resize the straight body. The host owns the split layout, existing canvas, scene replacement, material/artwork preservation and Undo. See [0.65.0](../../docs/release-0650.md).

## Walls, contents and editable labels (0.15.0)

The live profile accepts `wallMm`, `material`, `color`, `roughness`, optional `optics { color, opacity, ior, tintDistanceMm }` and optional `contents { type, fillPercent, color, opacity, viscosity }`. `ContentPresets`, `ValidateContents` and `ValidateOptics` are neutral exports. `BottleFill` clips the generated inner cavity, keeps a small wall clearance and closes the free surface. Viscosity is metadata for this static presentation. The host maps glass absorption/refraction and smoothly composites contents into the transmission background.

Artwork optionally carries `source { kind: svg, svg }` or `source { kind: text, ... }`. `ValidateLabelSource` and `TextLabelSVG` retain neutral authoring data; the browser host sanitizes/rasterizes SVG and supplies the PNG material resource. The panel's `artworkText` callback shares the host's live artwork transaction. Profile options expose the module's existing artwork UI; the host mounts it and restores its availability when the editor closes. The 0.16.0 host bridge can explicitly convert this source into the shared CAD editor. See [0.66.0](../../docs/release-0660.md) for supported SVG features, command units and rendering limits.


## Live glass construction and label CAD (0.16.0)

New bottle defaults and bottle catalog presets use glass. Round, oval and rounded-rectangle glass bottles have an open-mouth shell with separate outer/inner surfaces, a rim and a solid base; the separate cap has an inner cavity and printable top. Saved explicit plastic/PET or other material choices remain available. `GlassThicknessPresets` supplies nominal lightweight/standard/heavy wall-and-base pairs (1.2/2.4, 2/4 and 3/6 mm), with custom values and geometry-dependent fit limits. These are presentation presets, not supplier specifications or certified uniform-wall tooling.

`details` accepts `glassPreset`, `wallMm`, `baseMm`, `capWallMm`, `capMaterial` and `capColor`; existing `closure` selects smooth, ribbed or flip-top styling. Cap materials are PP, HDPE, aluminum and steel. `BottleWall`, `BottleCap` and the limit helpers provide the same construction values used by geometry, controls and label zones. The cap remains a separate component with its own material. Physical glass controls keep transmission, IOR, tint and wall thickness in the existing renderer/export path.

The neutral panel offers `liveConfigure`, `liveBlocked`, `fitSelected` and `openLabelCAD(zone)` callbacks. Auto3D synchronizes selected product definitions, queues rapid changes, validates label fit before replacement and preserves identity, transforms, compatible custom surfaces and artwork. Live edits keep the current camera; Fit selected is an explicit action.

`ValidateLabelCAD`, `NewLabelCAD`, `ScaleLabelCAD` and `LabelCADSVG` provide a host-independent label path contract. Optional `artwork[].cad` stores `{version:1,widthMm,heightMm,vectorized,paths}` in millimeters. Paths are closed `cut` outlines or `artwork` polylines/polygons with solid `fill`, `stroke` and `strokeWidth`. Each profile is bounded to 100 paths/2,000 points; paths stay within the physical label sheet. Combined editable artwork metadata is limited to 240,000 characters within the existing archive budget. Mapping and whole-product artwork scaling also scale the saved CAD coordinates.

The host opens the existing Packaging CAD editor through a neutral external-profile binding. Body front/back or wrap labels and `cap-top` use that same editor; cap labels start with a circular cut outline and must fit the cap disc. Cut outlines clip the applied PNG, including holes. Opening or editing CAD leaves the model unchanged until Apply; Apply renders the vectors into the normal portable label resource and saves the editable CAD beside it. Undo restores the prior artwork. Closing the editor preserves the existing model. File/recovery round trips retain CAD paths, label placement, finish and texture; ordinary GLB/glTF retains the baked appearance.

Compatible self-contained SVG shapes become editable paths, with curved segments flattened to a bounded 0.025 mm approximation. The converter allows up to 80 artwork paths/1,800 points, leaving room for the cut outline. Text, raster images and unsupported SVG paint use an explicitly disclosed color trace: up to eight colors, adaptive sampling from 128 down to 8 pixels on the longest side, and thresholded partial transparency. The result can lose detail and is shown for review before Apply; it is not font outlining or a lossless image-to-vector conversion. Original text/SVG/image import remains available outside this conversion workflow. Applying derived CAD replaces the active label source; the previous source is retained by normal Undo rather than embedded as another image in metadata.

Host commands include `primary.live.configure`, `primary.fit`, `primary.label.cad.open/inspect/apply` and shared `packaging.path.*` / `packaging.artwork.style`. The bridge checks account, session, selection and conversion generation before mutation and invalidates stale work. See [the current UI contract](../../docs/primary-products-ui.md).
