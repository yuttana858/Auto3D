# Saved Library sharing, import and mobile AR

Every Account, Device and published Library card has **Share**. The dialog generates a uniform four-digit code including leading zeros. **Generate viewer link** creates an independent read-only snapshot, returns a mini-viewer URL and automatically draws a QR code locally. The QR contains the URL only; give the code separately. Device saves upload their archive explicitly when Generate is clicked. Account/published saves copy an authorized archive server-side; they do not become globally published Library items.

Links default to 30 days, with downloads hidden. Agent creation supports 1–90 days and optional downloads. Codes are shown at creation and are not recoverable from the saved link list. Existing links are listed in the Share dialog with expiry and revocation; generate a new link/code if the code is lost. Revoke ends access and deletes that link's snapshot without changing the saved Library item. Deleting or modifying the original save does not alter an existing snapshot. Expiry ends viewing; revocation releases its stored bytes. Snapshots stay private in R2 under a dedicated audience prefix.

The audience uses `/mini.html?share=<uuid>` without an Auto3D account. Only GET metadata and POST archive/download challenges for exact audience UUID routes bypass account middleware; owner creation/list/revoke and all other APIs remain authenticated. A required Origin check protects POST challenges. The four-digit code is posted in JSON, never embedded in the URL or QR. Binary responses are private/no-store. HMAC hashes use a server secret; neither hashes, R2 keys nor owner IDs are returned publicly. Hiding Download is a product control, not DRM: displaying a 3D model necessarily delivers its data to the browser.

Verification is serialized in PostgreSQL. Five failures per share/IP in fifteen minutes produce a thirty-minute actor lock. Thirty aggregate failures per share in fifteen minutes produce a thirty-minute link lock, including attempts from different IPs. Successful challenges do not reset aggregate failures. HTTP 429 includes Retry-After; an absent trusted Cloudflare IP fails closed. Expired, pending and revoked links cannot grant access. Tables and invoker RPCs are service-role-only, with RLS enabled and browser-role grants revoked.

A share is limited to 32 MiB; each owner has a separate share-snapshot reservation budget of 1 GiB and 1,000 retained snapshots. Pending reservations count. Upload failures release storage/metadata only after successful cleanup; failed cleanup retains a reservation. Revocation during creation cannot resurrect a revoked link. Expired snapshots still occupy storage until revoked; scheduled cleanup is future work.

## Rollout

Production activation started on 2026-10-21 for Auto3D 0.37.1 / Packaging 1.7.1 (merged PR #38, commit `c8b26ed`). The audience migration is applied, the server-only random secret is configured, and the production readiness flag is true. The existing private R2 binding and Supabase settings were preserved. Redeployment `c8a5932c-c950-44e1-9f14-08075d62e530` binds the new settings successfully; see the latest activation entry in project-status.md for verification and remaining mobile smoke testing. Development itself made no live changes. Apply `supabase/migrations/20261020223655_audience_library_sharing.sql` through the reviewed deployment workflow, configure a random server-only `AUTO3D_AUDIENCE_SECRET` of at least 32 characters and the existing R2 binding, and then enable `AUTO3D_AUDIENCE_SHARING_READY=true`. Deploy the matching API, main and mini bundles together. Existing legacy `/api/share` and published Library permissions are unchanged. Do not enable the old PIN flag as a substitute.

Before enabling, run the PostgreSQL 17 tests in order: `test/security/audience-bootstrap.sql`, the new migration, and `test/security/audience-access.sql`, against a disposable database. CI runs this check. It verifies effective permissions, invoker mode, correct/wrong codes, actor/global lockout, recovery, expiry and revocation. Browser fixtures verify the default code/QR, incorrect/correct code, anonymous mobile rendering, Library Add and group navigation. A production smoke test remains required after rollout, including expiry/revocation and a real mobile device.

Commands share the UI services: `library.share.open`, `library.share.create`, `library.share.list`, `library.share.revoke`. Opening is interactive and does not upload. Creation is an explicit remote action and returns the code/link. `library.saved.open` accepts account/device/published, id and append; `library.account.open` retains its existing interface and now delegates to the same import service.

## Library Add and scene navigation

Open/Add now locks edits during archive fetching, reports download versus read/render status, rechecks account/workspace, and records sanitized failures in console/Error logs and the visible status. Appending stages new objects with fresh group/keyframe identities; successful imports preserve the existing document, selection workflow, camera/timeline settings and one Undo step. Failed imports roll back the added objects, mesh/material allocations and selection. Empty saves and the 1,000-object cap fail explicitly. The asynchronous mesh converter now passes failures to the awaiting import instead of leaving it pending indefinitely. This is a confirmed general failure path; the exact production REDCON archive has not been downloaded/tested because the managed runtime blocks its R2 endpoint.

Arrays appear as **Array group of … (count)**; ordinary groups use their saved name/count. Both Scene objects and the Meshes tree support collapsed group rows without changing engine geometry, placements or memberships. Expansion persists within the open session, including normal rerenders. Selecting a member does not force a collapsed group open. `scene.groups.inspect` and `scene.group.expand` expose the same state. Group data still persists in the archive; expansion is presentation state only.

## AR recommendation (not implemented)

Add a **View in your space** action after code verification. Recommend WebXR hit testing on supported Android browsers and USDZ/Quick Look fallback on iPhone/iPad, retaining ordinary 3D viewing elsewhere. The flow should ask for camera permission, find a horizontal surface, show a placement reticle and place the model on tap. Provide actual size and explicit display-scale controls. Known units convert to meters for AR; unknown units require a unit/size choice. Multi-object scenes need a documented world-unit convention before claiming actual-size alignment, because current scenes can contain independently imported units. AR placement is a visual presentation, not a measurement instrument; CAD and Measurement-layer values remain authoritative.

WebXR can reuse verified in-memory geometry. Native viewers need GLB/USDZ data; private challenge-bound files must not become permanent public URLs just to launch a native viewer. Use generated local assets where supported or short-lived, scoped grants with revocation checks. Device capability and physical surface placement need real Android/iOS tests before enabling AR.

References: [model-viewer AR modes and placement](https://modelviewer.dev/examples/augmentedreality/), [WebXR session features and permissions](https://developer.mozilla.org/en-US/docs/Web/API/XRSystem/requestSession).
