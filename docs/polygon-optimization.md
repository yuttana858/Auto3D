# Polygon optimization, arrays and selection

Model data's upper W/L/H fields are editable in the account's display units. Proportional scaling applies the edited dimension's ratio to all three axes; the percentage input multiplies the current size uniformly (100% leaves it unchanged). Position inputs and measured distances use display units, areas use squared units, and volumes use cubed units. Angles remain degrees and animation time remains seconds. Undeclared source units stay explicitly labelled model units: do not infer physical dimensions from an unlabelled mesh. Agent object.transform defaults to model coordinates for compatibility; units=display is explicit. selection.transform defaults to display units.

The Optimize polygons button sits beneath Triangles. meshoptimizer 1.3.0 runs in a bundled Web Worker. It simplifies independently by material and smoothing group, welds identical complete corner attributes, weights normals/UVs/colors, and locks open borders. It never uses permissive or sloppy simplification. Existing vertex values are reused; unused vertices and attributes are compacted, line geometry and material assignments are retained. Animated rigs/morph clips are excluded to preserve their topology. This is lossy static mesh optimization, not a guarantee of unchanged appearance or CAD accuracy.

The default relative error limit is 0.1% of mesh extent; the UI reports actual before/after counts. Dense seam-heavy/faceted models can stop early. Retain percentage is a target, not a guaranteed result. Drag the rotatable preview to inspect surfaces and silhouettes before applying. Preview leaves reachable scene geometry unchanged. Apply checks the scene revision and object membership; intervening edits require a fresh preview. Undo restores original meshes. Cancel terminates background work. Preview is never silently applied on save or upload.

Array dialogs allow retained-triangle selection and an instanced group preview. Values below 100% require preview before Create array; creation explicitly applies the selected source optimization and then creates copies (two undo operations). Original bounds determine array spacing. Automatic grouping defaults on and is optional. Groups persist as _auto3dGroup/_auto3dGroupName object metadata; select any member to select the group. Ctrl-click (Command-click on macOS) adds objects/groups to selection in both viewport and object list. Group/ungroup buttons are below the object list. Move/rotate/scale gizmos transform the selection about its combined bounds; Delete, Hide and Duplicate act on the selection. Top W/L/H edits and percentage scaling act on the active object. Group transforms with rotated objects and nonuniform scale use Three.js TRS decomposition; avoid assuming arbitrary shear is representable.

Array copies share immutable engine mesh references and converted GPU geometry while retaining distinct object IDs and picking metadata. Optimization applies new mesh references only to selected nodes, preserving other instances; portable compaction/export stores reachable meshes. Rendering cost still increases with instance count and visible triangles. An array preview uses GPU instancing; the editable scene uses individual meshes sharing buffers for selection/material compatibility. Use actual preview counts to choose sensible array sizes rather than assuming large copies are free.

Builds must bundle source/website/polygonworker.js as o3dv.optimize.js beside the main script. The local dev server has the same worker entry point. Commands: polygon.preview/apply/cancel, ui.polygons, object.scaling.proportional/percent, object.group/ungroup, object.select additive/single, selection.transform, and object.array autoGroup.

Research sources: [meshoptimizer JavaScript simplifier API](https://github.com/zeux/meshoptimizer/blob/master/js/README.md), [meshoptimizer simplification and seam constraints](https://github.com/zeux/meshoptimizer#simplification). Attribute-aware, error-limited simplification was selected because the application handles textured imported meshes whose UV seams and material boundaries must survive. Targets cannot guarantee visual quality; preview is part of the workflow.

For dense input the worker processes at most 200,000 triangles per material/smoothing batch, locking batch borders to avoid cracks and limit peak simplifier memory. Extremely large imported models still require substantial memory for source geometry, previews and Undo; desktop browser use is recommended for multi-million-triangle assets. A synthetic 3,001,250-triangle planar mesh was used for a simplifier stress check; it is not a guarantee for every topology or device.

The final synthetic stress run retained 1,501,250 of 3,001,250 triangles in 38.9 seconds, with measured relative error about 4.3e-7 and approximately 902 MiB Node RSS for the standalone packed-mesh simplifier. This measures a planar UV-mapped grid on the development host; browser source geometry, preview rendering and Undo add memory, and seam-heavy production models may reduce less. It is not a frame-rate or mobile benchmark.
