# Library share presentation and optimization review

Saved session archives contain object geometry, material values and texture bytes, object transforms and visibility, plus the saved camera, background, lighting and effects. Audience shares copy the saved archive; they do not capture later unsaved scene changes. The mini viewer reconstructs geometry and materials, camera, background, ground settings and supported HDRI/effects. It can fall back to default lighting if an HDRI cannot load; visual parity depends on the viewer's available effects and device. Animated assets and per-part visibility need separate end-to-end verification; do not claim full parity without it.

Shares currently store one archive per link, limited to 32 MiB. The viewer downloads that same archive on desktop and mobile. The existing polygon optimizer operates on editable session objects and explicitly avoids animated topology. It cannot safely produce a mobile variant of a saved Library archive without further work. A 5 MiB archive size is an advisory threshold, not a measure of GPU memory or render cost; textures and geometry can expand considerably after loading.

A future variant workflow should prepare an isolated copy of the saved archive, preserve original Library data, camera, materials and object transforms, reject or preserve animated and CAD-parametric content, and report actual triangle and byte changes before publication. The backend must securely store and account for both original and optimized variants, validate their association with the share, and delete both on revocation. The viewer needs a reversible quality choice and reliable fallback; screen size alone is not a reliable performance test. Add tests for access control, existing links, storage quota, revocation, malformed variants and visual parity before deployment.
