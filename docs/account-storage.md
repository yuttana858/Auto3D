# Account preferences and private Library

Every signed-in account automatically receives default preferences at first load. The client waits for account initialization before showing the workspace or permitting commands. The authenticated Supabase UUID is the owner; browser-supplied email, role, metadata and file keys never establish ownership. A captured request carries `X-Auto3D-Account`, which middleware compares with the verified identity to reject requests racing an account switch.

Preferences (`/api/preferences`) store theme, units, viewport/background/edge settings, camera navigation/projection, and folder paths in `auto3d_preferences`. Values are validated, credentials are excluded, and folder updates do not overwrite preferences. Changes are serialized and saved automatically. Cross-device simultaneous changes use last successful write. AI connection credentials remain on the device under an account-specific storage key and never enter preference records or portable sessions.

Account Library is the default Library tab and the default destination of Save current session. Ctrl+S/Save session file still opens the portable file dialog, with Account and Device destinations available. Uploads remain explicit actions; imported models and device files are not silently uploaded. Account saves use existing v5 archives without changing the portable format.

`AccountLibrary` and `/api/personal/items` provide list/save/get/archive/thumbnail/rename/move/delete. Account folders support create/rename/delete (folder deletion moves items to the parent; it does not delete files). Multi-item folder operations are sequential: a network failure may leave some moves completed. Reload the Library and retry. Device storage and crash recovery use `sw-auto3d-library-<user UUID>`; the previous unassigned database is preserved, but is not automatically exposed to or claimed by another account.

Private metadata is in `auto3d_personal_library`, separate from the legacy published catalog. Files use the existing Pages binding `AUTO3D_LIBRARY_R2` to private bucket `auto3d-library`. Managed r2.dev access is disabled and no custom domains expose that bucket. Keys are generated on the server as `users/<owner UUID>/<random item UUID>/session.auto3d` and `thumbnail.png`. Every metadata and file lookup is owner-filtered, including previews and known-ID requests. Private responses are `private, no-store`; no signed or public object URL is sent to the client.

Limits: 32 MiB archive, 1 MiB PNG preview, 1 GiB reserved archive/preview storage and 1,000 saves per account. Quotas include archive bytes, preview bytes and pending reservations and are serialized per owner in `auto3d_reserve_personal_item`. Oversized saves can still use File on disk. ZIP/PNG signatures and metadata are validated before reservation. A save becomes visible only after both R2 writes succeed. On failure the server deletes the partial objects and reservation. If cleanup fails or the process stops, the hidden pending entry remains for administrator reconciliation; inspect the matching R2 keys before removing it. Deletion hides an item before file removal and restores its record for retry after a definitive failure.

Database setup: `database/account-storage.sql`, applied as `account_preferences_and_private_library` with the additional `personal_library_item_limit` migration. Both tables have RLS ownership policies but no `anon`/`authenticated` table grants; the server uses its secret key with explicit owner filters. RPC execution is service-role only. On future Entra migration, map the external identity to the same durable account UUID; do not key files by email. Revoke sessions and remove owned R2 objects as part of user offboarding before deleting the Auth user; FK cascade alone does not delete R2 objects.

Commands: `preferences.inspect/theme/units`, `library.account.list/save/open/rename/move/delete`, and `library.account.folder.create/rename/delete`. UI and agents use the same storage methods. Read-only viewers cannot upload or mutate Library items. Save commands complete the upload; `ui.save` only opens a dialog. The catalog is generated with `npm run build_command_catalog`.

Validation: unit/API isolation, upload cleanup, quota refusal, strict schemas, expired/changed account responses, command/macros and read-only cases; browser round-trip of actual archives/previews with mocked database/R2; desktop/mobile login and layout tests; live SQL verification of service-role reservations, RLS/grants and recovery eligibility. Local `npm start` does not execute Pages Functions; integrated browser tests intercept API calls and run the real handlers against in-memory adapters.

## Release 0.27.1: preference loading and unsaved recovery

Account preferences load once per identity and replace cookie/previous-account defaults before the viewport paints. Viewport application is batched; explicit light/dark/custom background choices remain independent of the Appearance theme. Logout invalidates in-flight preference reads and queued writes, including same-account re-login. Color snapshots use integer components accepted by the API.

Preferences → Recover unsaved session reopens the device recovery dialog for an empty workspace. Valid recovery stays in IndexedDB until an explicit full-session save. Invalid checkpoints remain available for inspection and show their actual validation error; they are not silently discarded or loaded over an occupied/read-only workspace. Recovery is scoped to the signed-in account/device. `session.recovery.inspect`, `session.recovery.open` (interactive), and `session.recovery.restore` share these services. `preferences.viewport.inspect` reports the applied background/loading state.

The header and Preferences show v0.27.1. Preferences also shows the build commit (Cloudflare Pages/GitHub SHA, or the bundle digest when no commit is provided). `app.version.inspect` returns the running version and build. A merged PR still needs a successful Pages deployment before its version appears in the live app. PR #21 introduced metallic fill and floor-shadow isolation while retaining the old v0.27.0 label; it did not contain this recovery release.
